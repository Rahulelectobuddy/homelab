# Disaster Recovery Runbook

This guide details how to restore **Nextcloud AIO**, **Vikunja**, **n8n**, **Vaultwarden**, **Zulip**, and **SFTPGo** onto a clean host out of the box.

## 1. Prepare Environment

On the target server:
1. Install Docker Engine and the Docker Compose plugin.
2. Clone this repository:
   ```bash
   git clone <YOUR_REPO> /opt/homelab
   cd /opt/homelab
   ```
3. Restore `/opt/homelab/.env` from your secret store.

## 2. Option A: Restore from Docker Volume Archives

Recover Zulip separately using section 5 and SFTPGo using section 6. In sections
2 and 3, pass explicit service names to `docker compose up` so these services do
not start before recovery:
`n8n-postgres n8n vikunja-mariadb vikunja vaultwarden nextcloud-aio-mastercontainer`.

If restoring from volume archives generated by `backup.sh`:

1. Initialize stack volumes without starting containers:
   ```bash
   docker compose up --no-start
   ```

2. Extract volume archives into Docker named volumes:
   ```bash
   RESTORE_DIR="/opt/backups/homelab/<DATE>/volumes"

   for vol in n8n_data n8n_db_data vikunja_files vikunja_db_data vaultwarden_data nextcloud_aio_mastercontainer; do
     FULL_VOL=$(docker volume ls -q | grep "_${vol}$" || echo "$vol")
     if [ -f "$RESTORE_DIR/${vol}.tgz" ]; then
       echo "Restoring $vol into $FULL_VOL..."
       docker run --rm -v "${FULL_VOL}:/target" -v "$RESTORE_DIR:/backup" alpine:3.20 \
         tar xzf "/backup/${vol}.tgz" -C /target
     fi
   done
   ```

3. Start services:
   ```bash
   docker compose up -d n8n-postgres n8n vikunja-mariadb vikunja vaultwarden nextcloud-aio-mastercontainer
   ```

## 3. Option B: Restore from Database Dumps

1. Start database containers:
   ```bash
   docker compose up -d n8n-postgres vikunja-mariadb
   ```

2. Restore database dumps:
   - **n8n PostgreSQL**:
     ```bash
     gunzip -c n8n.sql.gz | docker compose exec -T n8n-postgres psql -U n8n -d n8n
     ```
   - **Vikunja MariaDB**:
     ```bash
     gunzip -c vikunja.sql.gz | docker compose exec -T vikunja-mariadb mariadb -u root -p"$VIKUNJA_DB_ROOT_PASSWORD" vikunja
     ```

3. Start remaining services:
   ```bash
   docker compose up -d n8n-postgres n8n vikunja-mariadb vikunja vaultwarden nextcloud-aio-mastercontainer
   ```

## 4. Nextcloud AIO Restoration

Nextcloud AIO manages its child containers automatically. To restore Nextcloud AIO:
1. Open the AIO Interface at `https://<YOUR_SERVER_IP>:8080`.
2. Select **Restore from Backup**.
3. Enter your BorgBackup directory path (e.g. `/opt/backups/nextcloud`) and your secret encryption passphrase.
4. Nextcloud AIO will automatically restore all databases, apps, and user data and start child containers out of the box.

## 5. Zulip Restoration

On a clean target host, restore the private `compose.yml` with the original
inline Zulip credentials. Keep the Zulip application stopped until its database
has been restored. Restore `zulip_data.tgz` and the SQL dump it contains;
RabbitMQ and Redis can start with fresh volumes. Do not restore a live
PostgreSQL data-directory archive.

```bash
cd /opt/homelab
docker compose stop zulip
RESTORE_DIR="/opt/backups/homelab/<DATE>/volumes"
# Uses the compose-managed zulip_data volume without starting dependencies.
docker compose run --rm --no-deps -v "$RESTORE_DIR:/backup:ro" zulip \
  tar xzf /backup/zulip_data.tgz -C /data
docker compose run --rm --no-deps zulip ls /data/backups
# Choose the most recent backup-*.sql listed above.
docker compose run --rm zulip app:restore 'backup-<TIMESTAMP>.sql'
docker compose up -d --wait zulip
```

Ensure the host-based Cloudflare Tunnel routes `talk.cypherlifeos.space` to
`http://127.0.0.1:8090`, then verify login, existing messages, and file uploads.
For an existing installation, take a new backup first: restoring a database
replaces its current contents. See the official
[Zulip Docker backup guide](https://zulip.readthedocs.io/projects/docker/en/latest/how-to/compose-backups.html).





## 6. SFTPGo Restoration

Restore `sftpgo_data.tgz` and `sftpgo_config.tgz` from the same backup timestamp.
They contain vault files and the SQLite user/admin database, settings, and SSH
host keys. Use empty target volumes on a clean host; extracting into an existing
installation merges files and does not remove newer files. Back up an existing
installation before restoring it.

```bash
cd /opt/homelab
docker compose stop sftpgo
RESTORE_DIR="/opt/backups/homelab/<DATE>/volumes"
# Uses the service's own volume mounts; root preserves archived UID/GID.
# Overriding the entrypoint prevents the server from starting during extraction.
docker compose run --rm --no-deps --user 0:0 --entrypoint sh \
  -v "$RESTORE_DIR:/backup:ro" sftpgo -ec '
    tar xzf /backup/sftpgo_data.tgz -C /srv/sftpgo
    tar xzf /backup/sftpgo_config.tgz -C /var/lib/sftpgo
  '
docker compose up -d sftpgo
```

Restore the previous `compose.yml` port mappings and HTTPS tunnel route if used.
Verify admin login and the Obsidian plugin connection check, then confirm that
existing notes can be read and a temporary note syncs between devices.
