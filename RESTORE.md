# Disaster Recovery Runbook

This guide details how to restore **Nextcloud AIO**, **Vikunja**, and **n8n** onto a clean host out of the box.

## 1. Prepare Environment

On the target server:
1. Install Docker Engine and the Docker Compose plugin.
2. Clone this repository:
   ```bash
   git clone <YOUR_REPO> /opt/homelab
   cd /opt/homelab
   ```
3. Restore `/opt/homelab/.env` from your secret store.

## 2. Option A: Restore from Docker Volume Archives

If restoring from volume archives generated by `backup.sh`:

1. Initialize stack volumes without starting containers:
   ```bash
   docker-compose up --no-start
   ```

2. Extract volume archives into Docker named volumes:
   ```bash
   RESTORE_DIR="/opt/backups/homelab/<DATE>/volumes"

   for vol in n8n_data n8n_db_data vikunja_files vikunja_db_data nextcloud_aio_mastercontainer; do
     FULL_VOL=$(docker volume ls -q | grep "_${vol}$" || echo "$vol")
     if [ -f "$RESTORE_DIR/${vol}.tgz" ]; then
       echo "Restoring $vol into $FULL_VOL..."
       docker run --rm -v "${FULL_VOL}:/target" -v "$RESTORE_DIR:/backup" alpine:3.20 \
         tar xzf "/backup/${vol}.tgz" -C /target
     fi
   done
   ```

3. Start services:
   ```bash
   docker-compose up -d
   ```

## 3. Option B: Restore from Database Dumps

1. Start database containers:
   ```bash
   docker-compose up -d n8n-postgres vikunja-mariadb
   ```

2. Restore database dumps:
   - **n8n PostgreSQL**:
     ```bash
     gunzip -c n8n.sql.gz | docker-compose exec -T n8n-postgres psql -U n8n -d n8n
     ```
   - **Vikunja MariaDB**:
     ```bash
     gunzip -c vikunja.sql.gz | docker-compose exec -T vikunja-mariadb mariadb -u root -p"$VIKUNJA_DB_ROOT_PASSWORD" vikunja
     ```

3. Start remaining services:
   ```bash
   docker-compose up -d
   ```

## 4. Nextcloud AIO

Nextcloud AIO manages its child containers automatically. Master container state is restored with the `nextcloud_aio_mastercontainer` volume archive, after which the Nextcloud AIO interface will automatically pick up existing data.
